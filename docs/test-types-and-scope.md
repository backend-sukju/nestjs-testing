# 무엇을 쓰는가 — 테스트 종류와 범위 (실행 가능한 예시)

`src/raffle/` 의 API 하나(`GET /raffle/:round/winners`)를 두 층위로 테스트해, "테스트 종류"와 "무엇을 확인하는가"가 별개의 축임을 보여줍니다.

## 도메인 — 사고와 같은 구조

외부 "상금풀 서버"는 **등수별 총액(합계)** 과 **인원**을 준다. 우리 서버는 **1인당 = 총액 ÷ 인원**을 계산해 내려준다.

```
[외부 상금풀 서버]  totalCash(합계) + winnerCount(인원)
        │
        ▼  1인당 = 총액 ÷ 인원  ← 의미가 뒤바뀌기 쉬운 지점
[우리 서버]  cashPerUser(1인당)
        │
        ▼
[응답]  { round, winners: [{ rank, cashPerUser }] }
```

이 값은 **의미 검증이 꼭 필요한** 세 조건을 동시에 만족한다: 파생값(합계 ÷ 인원), 동명이의(총액 vs 1인당), 다경로(외부→우리→응답).

## 4-1. 두 가지 질문으로 나눈다

### 질문 1 — 무엇을 진짜로 두는가? (외부를 진짜 부르는가?)

| 종류 | 이 예시의 파일 | 앱 부팅 | 외부(PrizePoolClient) |
|---|---|---|---|
| **Unit** | `src/raffle/raffle.service.spec.ts` | ❌ 안 띄움 | mock (생성자 주입) |
| **API 테스트 (주력)** | `test/raffle.e2e-spec.ts` | ✅ 띄움 | mock (`overrideProvider`) |
| 실연동 | (이 예시엔 없음) | ✅ | **진짜** 호출 |

> NestJS는 뒤의 둘을 다 "E2E"라 부른다(그래서 `*.e2e-spec.ts`). 이름 논쟁 대신 각 테스트 상단에 **"무엇을 mock했는지"**만 적었다. 두 spec 파일의 헤더 주석을 보라.

핵심 기법 — 앱은 진짜 부팅하되 외부만 갈아끼운다:

```ts
Test.createTestingModule({ imports: [AppModule] })
  .overrideProvider(PrizePoolClient)   // 외부 서버 클라이언트만
  .useValue({ getRankPrizes })         // mock으로 교체
  .compile();
```

### 질문 2 — 무엇을 확인하는가?

| | 뜻 | 이 예시의 테스트 |
|---|---|---|
| 로직 | 계산이 맞나 | `1인당 = 총액 ÷ 인원`, 내림 |
| 조립 | 라우팅·인증·직렬화가 맞물리나 | 401/400, 응답 구조 |
| **의미 ⭐** | 값의 뜻이 약속과 맞나 | `cashPerUser`는 1인당인가 총액인가 |

**두 질문은 별개다.** 아무리 넓게 태워도(질문1) 의미를 단언하지 않으면(질문2) 값 의미 불일치는 안 잡힌다. 아래에서 실측으로 증명한다.

## 4-2 / 4-3. Happy path만으론 부족 — 체크리스트를 API 테스트로

`test/raffle.e2e-spec.ts` 는 신규 API 체크리스트를 한 엔드포인트에 적용한다:

| 체크리스트 | 테스트 | 확인 |
|---|---|---|
| 계약 — 인증 분기 | `[계약] API 키가 없으면 401` | 인증 |
| 계약 — 파라미터 | `[계약] round가 숫자가 아니면 400` | ParseIntPipe |
| 계약 — 응답 구조 / 동작 | `[동작] … { round, winners[] }` | 라우팅·직렬화·매핑 |
| **의미 ⭐** | `[의미] cashPerUser는 … 총액이 아니다` | 값의 뜻 |
| 경계·이상 | `[경계] 당첨자 없는 회차 → 빈 배열` | 빈 값 |
| 경계·이상 | `[이상] 외부 실패 → 503` | 실패 안전장치 |

(멱등성·동시성은 상태를 바꾸는 API에만 필요 → 이 조회 API엔 "없음 + 이유"로 처리)

## "넓게 태우기 ≠ 의미 검증" — 변이로 증명

`raffle.service.ts`에서 1인당 계산을 **총액 그대로 매핑**하도록 바꿔(= 실제 사고 재현) 테스트를 돌리면:

```ts
// 변이: cashPerUser: this.perUser(r.totalCash, r.winnerCount)
//   →   cashPerUser: r.totalCash
```

| 테스트 | 결과 |
|---|---|
| `[계약] 401` | 🟢 통과 |
| `[계약] 400` | 🟢 통과 |
| `[경계] 빈 배열` | 🟢 통과 |
| `[이상] 503` | 🟢 통과 |
| `[동작] 값 단언` | 🔴 **잡음** |
| `[의미 ⭐]` | 🔴 **잡음** |

인증·파라미터·경계·외부실패를 **아무리 넓게 태워도** 사고를 그냥 통과시킨다. 오직 **값의 의미를 단언한 테스트만** 빨간불이 뜬다 — 이게 4-1 질문2의 핵심이다.
